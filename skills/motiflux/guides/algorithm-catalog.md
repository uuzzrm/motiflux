# Motiflux algorithm catalog

Use this catalog after identity and topology are known. A theme selects a small
algorithm stack; it does not authorize every effect in that stack. Every
selected family needs a motion-language rationale and a QA check.

| Algorithm family | Best for | Core controls | Main proof |
| --- | --- | --- | --- |
| `path-reveal` | line marks and contour-first logos | traversal, arc intervals, stroke state | no early branch, monotonic progress |
| `mask-aperture` | editorial, security, cinematic reveals | aperture, exposure, focal order | silhouette readability, safe crop |
| `spatial-staging` | product and system marks | anchors, hierarchy, container bounds | spatial continuity, no layout shift |
| `spring-settle` | confirmation and friendly interaction | damping, mass, overshoot limit | bounded settle, no identity distortion |
| `kinematic-trajectory` | automotive, industrial, precision | velocity, acceleration, jerk | continuity and transformed bounds |
| `signal-convergence` | AI and data themes | seed, density, field, convergence | deterministic landing, no fake data claim |
| `particle-secondary` | gaming and celebratory accents | count, seed, lifetime, opacity | hero mark remains legible, performance |
| `topology-occlusion` | self-crossing and braided marks | crossings, order, clips | no nonlocal early branch |
| `morph-interpolation` | compatible shape states | correspondence, winding, controls | topology compatibility, landmark error |
| `camera-parallax` | cinematic depth and title staging | depth, drift, exposure | final reading, crop safety |
| `kinetic-type` | wordmarks and title systems | glyph order, tracking, line rhythm | text identity, reading order |
| `state-machine` | loading, auth, payment, status | states, transitions, cancellation | no false success, interruptibility |
| `reduced-motion-substitution` | inclusive delivery | opacity, color, border, static fallback | semantic equivalence and focus |

Choose the smallest stack that explains the requested behavior. Combine families
only when their dependencies are explicit in `motion-plan.yaml`. Prefer
`reduced-motion-substitution` whenever movement is nonessential. Particles,
camera effects, and deformation are secondary layers and must not carry the only
identity-bearing information.
